# AGENTS.md

## Cursor Cloud specific instructions

Watchify is a single product: a **Next.js 14 web app** (`:3344`) plus a companion **Socket.io realtime server** (`:3345`), backed by **SQLite via Prisma** for local dev. The `native/` directory is a Capacitor iOS shell that requires macOS/Xcode and is not part of web development or testing here. Standard commands live in `package.json` scripts and `README.md`; only non-obvious caveats are captured below.

### Running the app
- `npm run dev` starts **both** the Next app (`:3344`) and the realtime server (`:3345`) together via `concurrently`. Use this for development — the app polls as a ~12s fallback if realtime is down, so live party features (chat sync, presence, playback sync) need the realtime process running.
- Health checks: web `GET http://localhost:3344/api/health` (reports `db`, stripe/email flags); realtime `GET http://localhost:3345/` returns `{"ok":true,"service":"watchify-realtime"}`.
- Demo logins (password `watchify-demo`): `alex@watchify.app` (admin), `jordan@watchify.app` (mod). The sign-in form at `/auth/signin` is pre-filled with alex's credentials in dev.

### Database (SQLite) — important caveat
- `prisma/schema.prisma` has **drift** from the committed migrations in `prisma/migrations/` (models like `Conversation`/`DirectMessage` and some columns exist only in the schema). Because of this, **do NOT run `npx prisma migrate dev`** for local setup — it will generate a spurious new migration file every time. Instead use **`npx prisma db push`**, which syncs the SQLite DB to `schema.prisma` without creating migration files.
- The dev database (`prisma/dev.db`) is gitignored and persists in the VM snapshot. To (re)create or reset it: `npx prisma db push` then `npm run db:seed` (or `npm run db:reset`, but note reset uses `migrate reset` and will hit the same drift). Seeding is safe to re-run.

### Environment
- `.env` (gitignored, persisted in snapshot) is created from `.env.example` with a generated `NEXTAUTH_SECRET`. Prisma reads `DATABASE_URL` from `.env`. If `.env` is ever missing, recreate it: `cp .env.example .env` and set `NEXTAUTH_SECRET` (e.g. `openssl rand -base64 32`).
- All external integrations degrade gracefully when keys are absent: Stripe → demo mode, email → Ethereal/console, TMDB → curated demo catalog, TURN → STUN-only. None are required to run or test core flows.

### Lint / test / build
- Lint: `npm run lint` (currently passes with a few pre-existing `react-hooks/exhaustive-deps` warnings — not errors).
- Test: `npm test` (Node test runner via `tsx`, `tests/week4.test.ts`).
- Build: `npm run build` runs `prisma generate && next build`. Prisma client is regenerated by the startup update script (`npx prisma generate`), so a fresh `node_modules` is safe.
